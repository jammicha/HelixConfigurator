Deploy via the OpenTelemetry Operator (auto-instrumentation)

This chart deploys the Helix gateway as an OpenTelemetryCollector custom resource and ships an Instrumentation custom resource, so you can auto-instrument apps (Java, Node.js, Python, .NET) with no code changes — just a pod annotation. It needs the OpenTelemetry Operator installed first.

1Install prerequisites

The Operator extends Kubernetes with two new resource types (the CRs this chart uses). Install cert-manager (for the Operator's admission-webhook certs), then the Operator. One-time, per cluster:

kubectl apply -f https://github.com/cert-manager/cert-manager/releases/download/v1.19.5/cert-manager.yaml
kubectl wait --for=condition=Available --timeout=180s -n cert-manager deploy/cert-manager-webhook

kubectl apply -f https://github.com/open-telemetry/opentelemetry-operator/releases/download/v0.152.0/opentelemetry-operator.yaml
kubectl rollout status -n opentelemetry-operator-system deploy/opentelemetry-operator-controller-manager --timeout=180s
Already running the Operator?
Skip this step. The chart only needs the OpenTelemetryCollector and Instrumentation CRDs to exist.

2Generate & download the chart

In the configurator's Prereqs & Generate step, pick which runtimes to auto-instrument, then Download chart (.zip). Unzip and cd in:

unzip helix-otel-operator-chart.zip
cd helix-otel-operator

Your HELIX_ENDPOINT and X_SOURCE are baked into values.yaml; your live collector pipeline becomes the CR's spec.config. Your API key is never written into the chart.

3Create the Helix API-key secret

kubectl create secret generic helix-key \
  --from-literal=HELIX_API_KEY='<TenantID>::<AccessKey>::<SecretKey>'
Already manage secrets your way?
--set helix.existingSecret=<your-secret-name> (it must expose a HELIX_API_KEY key).

4Install with Helm

helm install helix . --set helix.existingSecret=helix-key

Into a specific namespace, create the Secret there too:

kubectl create namespace observability
kubectl create secret generic helix-key -n observability \
  --from-literal=HELIX_API_KEY='<TenantID>::<AccessKey>::<SecretKey>'
helm install helix . -n observability --set helix.existingSecret=helix-key

The Operator reconciles the CR into a managed collector Deployment and a Service named helix-gateway-collector. The chart also adds a stable alias Service helix-gateway (on 4317/4318) so apps can use the familiar name.

5Annotate your pods

Add a pod-template annotation to your app's Deployment — the Operator injects the agent on the next rollout. No app image or code changes:

instrumentation.opentelemetry.io/inject-java:    "<namespace>/helix-instrumentation"
instrumentation.opentelemetry.io/inject-nodejs:  "<namespace>/helix-instrumentation"
instrumentation.opentelemetry.io/inject-python:  "<namespace>/helix-instrumentation"
instrumentation.opentelemetry.io/inject-dotnet:  "<namespace>/helix-instrumentation"

Apply to a running Deployment and roll it out:

kubectl patch deployment <app> -n <app-ns> -p \
  '{"spec":{"template":{"metadata":{"annotations":{"instrumentation.opentelemetry.io/inject-java":"<namespace>/helix-instrumentation"}}}}}'
Namespace rule
The Instrumentation CR is namespaced. Reference it as <namespace>/helix-instrumentation (where you installed the chart). The bare value "true" only works when the app is in that same namespace.

Prefer not to annotate? Apps can send OTLP straight to http://helix-gateway.<namespace>.svc.cluster.local:4318.

6Verify telemetry is flowing

The Operator reconciled the gateway

kubectl get opentelemetrycollector,pods -l app.kubernetes.io/component=opentelemetry-collector -n <namespace>

The agent was injected into your app

kubectl get pod <app-pod> -n <app-ns> \
  -o jsonpath='{.spec.initContainers[*].name}{"\n"}'

You should see an opentelemetry-auto-instrumentation-* init container.

See it in Helix

Open your tenant's OTel Namespace Overview dashboard — telemetry from your annotated apps should appear within a couple of minutes of the rollout.

?Troubleshooting

helm install fails: no matches for kind "OpenTelemetryCollector"

The Operator (or its CRDs) isn't installed. Do step 1 first, then retry.

Annotated a pod but no telemetry / no init container

The webhook only fires on pod creation — annotate the pod template (not the live pod) and roll out: kubectl rollout restart deployment/<app> -n <app-ns>. Confirm the annotation key matches the runtime, and the value's namespace points at where the chart is installed.

Apps in another namespace can't reach the gateway

Use the fully-qualified endpoint http://helix-gateway.<install-namespace>.svc.cluster.local:4318, and annotate with the <install-namespace>/helix-instrumentation form.

OpenShift / restricted Pod Security
The Operator and the collector run non-root. If a restricted-PSA namespace rejects the injected init container, grant the app's ServiceAccount the appropriate SCC or instrument via the direct-OTLP fallback instead.
